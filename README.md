# tagtoo-commerce-report：電商品牌分析報告（草稿）

> 狀態：草稿 v0.8.0（2026-11-03；程式改由專案檔案 `tcr-pkg.xlsx` 提供；流程已穩定，簡報內容調整中；精簡版 5 章 14–17 頁，A-2 可續頁）。這是 Wallace 新建的工具，不是既有的上游包，也不是客戶客製版。原本放在 `tagtoo-harness-packages` 的 `drafts/commerce-report/`，2026-11-02 獨立成本公開 repo 並定為正本：同事內部試用時直接 clone，不必有 GitHub 帳號。
>
> **用途**：給業務推廣、品牌客戶自己使用。設計前提是互動越少越好：客戶只回覆兩次（確認品牌與競品、確認摘要結論），不交草稿、不產 Excel。

用 Tagtoo Commerce MCP 查台灣三個電商平台（momo、PChome、蝦皮）的公開商品資料，產出品牌端的電商報告。形式比照 `brand-voice`、`competitive-ads`、`kol-recommendation`：一個 claude.ai Project，Instructions 加 knowledge 檔，用塔圖主題產 PPTX。

## Project 設定

**v0.8.0 起（先在測試專案「Commerce Report 上傳版測試」驗證）**：專案檔案放 3 個：`dist/tcr-pkg.xlsx`、`project-instructions.md`、`docs/report-format-spec.md`；「指示」欄貼：

```
【語言】回覆、進度說明與內部思考一律用繁體中文。

【全程】
・客戶看得到的每一句（包含工作中途的進度說明）都用繁體中文，不可出現英文句子。
・不建立任務清單（不呼叫 TaskCreate、TaskUpdate、TodoWrite）。
・不呼叫選項按鈕。要客戶回覆時，把表格整份印在回覆正文，最後一行寫清楚回覆方式（例：回「確認」就開始），整則回覆以那一行結束。
・不對客戶提程式、腳本或維運事項。
・回覆中不稱對方為「客戶」，也不說明自己跳過、執行或判斷了哪個步驟（例：不寫「客戶選了 A」「跳過第一題」）。

【開場】客戶第一句沒附品牌時，不呼叫任何工具，整則只回：
👋 我會用 momo、PChome、蝦皮的數據資料，幫你做一份電商品牌分析簡報。
**要分析哪個品牌與產品？**　例：`象印－保溫杯`

收到品牌後，同樣不呼叫任何工具，只問「〔品牌〕要不要和競品比較？」。用表格，不用按鈕，選項照抄，最後一行寫「👉 回 A、B＋品牌名，或 C」：
A 推薦 3 個：從 momo 同類商品的搜尋結果中，挑上架商品最多的 3 個品牌
B 我自己指定：最多 3 個，直接接著打品牌名，例：B 虎牌、膳魔師
C 不比較：只看〔品牌〕自己
客戶第一句已附品牌或競品時，跳過已回答的那題。

【之後】客戶回答完上面兩題，才用讀知識庫的工具（Projects，method project_read）讀完 project-instructions.md 與 report-format-spec.md 全文（不可只靠知識庫搜尋片段），再照 project-instructions.md「程式包」段把專案檔案 tcr-pkg.xlsx 解壓到 /home/claude/pkg/docs（不讀程式原始碼、不自己重打程式；第一個指令沒有給判定時，原樣重送一次），依 project-instructions.md 從步驟 ③ 繼續。回覆中不提解壓、檔名或指令。
```

【全程】三條寫在「指示」欄，是因為好神拖那場的任務清單在讀檔之前就建了，寫在檔案裡的規則管不到；確認表沒印、英文進度句也是檔案裡寫了仍發生，「指示」欄每一輪都會讀到、對話被壓縮也不會掉。

開場兩題寫在「指示」欄，是因為「指示」欄每一輪都直接放在 Claude 眼前，不用先讀檔；開場兩題不呼叫任何工具，回覆最快。v0.7.x 的 GitHub 版（add_repo＋clone）留在 git 歷史，BD 共用帳號跑 clone 下來的腳本會被擋，所以改成上傳版。

原因：GitHub 同步的檔案在 Project 裡**不能用檔名讀全文**，只能被搜尋到片段（2026-10-28 實測）。這次試跑前四輪都只靠片段在跑流程，到產 PPTX 時才自己 clone repo 拿到全文。

**釋出給客戶前** ◀ 待決定：本 repo 已公開，客戶也 clone 得到，可以沿用；或改成跟上游五個包一樣，把上表檔案直接上傳到 knowledge，「指示」欄改成一句指向 `project-instructions.md`。

## 實測紀錄

### 範例資料（2026-10-28）

- （v0.2）用 `deck_data.example.json` 跑三種情況，都在 15–18 頁內：比較模式全頁 18 頁、拿掉三個非必出頁 15 頁、單品牌模式 17 頁（不出折扣深度頁）。

- Wallace 在 PowerPoint 實際開啟 18 頁測試檔：沒有修復提示、排版沒有出錯。

### 真實品牌試跑：橘平屋 vs 元本山、orionjako、里仁（2026-10-28）

- `build.js` 第一次就建置成功，17 頁沒有警告；縮圖沒有破框。
- 發現並已在 v0.3 修正：
  1. 03-2 每克售價把客戶的轉賣價（PChome、蝦皮）和競品的 momo 官方價放在一起比 → 價格頁只用正規通路。
  2. 第三方轉賣只在 momo 剔除、蝦皮全部保留，口徑不一致 → 三平台都保留在通路頁、都不進價格頁。

  4. 對話輪數太多（確認 3 次、Markdown 草稿 1 次，另有一次工具額度用完停下）→ 改成客戶只回兩次，評論工具不呼叫。

- 專案知識庫的檔案不在執行環境：`/mnt/project` 不存在，`/mnt/user-data` 裡也沒有，全機找不到 analyze.py。
- Claude 有 Projects 工具（`project_read` 等 7 個方法）可讀知識庫全文，但文字檔一律直接回傳內容（連 13.5 萬字的合併檔也是），只有圖片、試算表等非文字檔才會原檔寫進執行環境；專案知識庫不收 zip。
- 所以上傳版只能讓 Claude 讀全文後自己重打成檔案：analyze.py 重打後可執行、沒被擋，但比原檔少 6 位元組（md5 不同）。全部檔案約 15 萬字，每場都要重打，耗時耗量，base64 圖檔（tagtoo_assets.js）重打出錯的風險最高。
- 結論：上傳版目前不可行，除非大幅縮小腳本與素材。

### 上傳版改用試算表容器（2026-11-03，Wallace 帳號與 BD 共用帳號）

- 更正上一段：官方 Brand Voice 等專案在同一環境也拿不到知識庫檔案，是每場由 Claude 重寫主題檔、建置腳本，所以「上傳版不可行」講得太滿。上次重打少 6 位元組，是 analyze.py 第 347 行 `\u4e00-\u9fff` 被轉成實際字元。
- 新做法：把 5 支程式與 `deck_data.example.json` 包進一個合法的 xlsx（`tcr-pkg.xlsx`，最小工作表＋`tcr/docs/` 底下的原檔，未壓縮）上傳到專案檔案。執行環境會把它原檔放在 `/mnt/user-data/attachments/<id>/<前8碼>-tcr-pkg.xlsx`，解壓即得原檔，不用重打。
- 實測（範例資料，不查電商）：Wallace 帳號與 BD 共用帳號結果相同：6 個檔 sha256 與 repo 完全一致；`npm install`、`build.js`（17 頁）、`analyze.py --help` 都沒被擋。唯一干擾是第一個 Bash 指令安全檢查「沒給判定」，原樣重送一次就過。
- 結論：上傳版可行，且解決了 BD 帳號 clone 下來的腳本被擋的問題。完整報告流程尚未用這個做法實跑。
